# 流程控制与 Agent 发挥边界

CareerFlow 不允许 Agent 端到端自由发挥。每个阶段都必须遵循同一条控制链：

```text
确定性输入检查
  -> Agent 在固定任务内生成候选内容
  -> 程序校验输出结构与来源约束
  -> 用户审阅并作不可替代的决定
  -> 程序执行文件写回、状态变化或外部操作
  -> 生成清单、哈希或回执
```

## 三类责任

| 类型 | 负责什么 | 谁执行 | 是否允许自由变化 |
|---|---|---|---|
| P：确定性流程 | 目录隔离、输入存在性、状态机、结构校验、哈希、文件编辑、邮件发送、回执和总复盘同步 | CareerFlow 程序 | 否。同一输入和配置应产生可核验的固定流程结果 |
| A：受限 Agent 判断 | 相关经历排序、忠实改写、求职信叙事、检索词与来源选择、问题预测、回答框架、复盘解释 | Agent | 仅允许在本阶段输入、证据边界和输出契约内变化 |
| H：人工决定 | 事实确认、内容取舍、最终审批、多个邮箱选择、是否发送、是否进入面试、结果与真实感受 | 用户 | 不得由 Agent 推断或代替 |

“Agent 发挥”不等于开放式创作。Agent 只能优化表达、组织和分析，不能改变事实、流程、权限或最终动作。

## 分阶段边界

| 阶段 | 必须流程化（P） | Agent 可发挥（A） | 必须由用户决定（H） | 程序验收 |
|---|---|---|---|---|
| 用户初始化 | 创建独立用户目录；校验 profile 字段；生成 evidence ledger | 从原简历提取候选事实、指出冲突和缺口 | 确认姓名、日期、数字、经历和技能 | profile/evidence 文件存在，事实均标记为已确认 |
| 新建岗位 | 一岗位一目录；保存完整 JD；状态设为 `created` | 拆解 JD 的职责和优先级 | 确认公司、岗位和 JD 完整性 | application 元数据和输入文件完整 |
| 简历与求职信 | 固定生成三件套；结构校验；写入契约清单 | 选择相关经历、重排顺序、忠实改写、组织求职信叙事 | 审批全部内容与证据映射 | 三个文件结构通过；主要表述可回溯；状态仅到 `drafted` |
| 原格式写回 | 模板识别、区域 ID、容量限制、哈希和视觉差异检查 | 把批准文案映射到已有区域 | 批准 document plan；目视确认最终文件 | 只修改批准区域；输出 manifest；不得绕过编辑器 |
| 邮件投递 | 从 JD 提取地址；固定命名规则；预览；哈希锁定；加密 SMTP；一次性发送与回执 | 根据 JD 明确命名要求提出附件名；把已批准求职信整理成正文 | 多地址选择、最终邮件审批、提供确认码、决定发送 | 收件人来自 JD；主题等于附件名；任一变化即失效；不确定结果禁止重试 |
| 面试准备 | 固定九段结构；联网输出必须有 URL；写入研究清单 | 搜索、判断来源相关性、综合业务流程、预测问题和设计回答框架 | 触发面试阶段；确认哪些问题需要重点练习 | 九段齐全且顺序固定；事实/推断/未知分开；在线结果无 TODO |
| 复盘 | 保存原始反馈；限制结果枚举；分类并同步岗位与总汇总 | 解释问题、归类、提出下一次改进动作 | 提供真实问题、感受、结果；确认长期规律 | 原始观察不丢失；单次经验不自动升级为稳定结论 |

## Agent 的六个可发挥区

Agent 只在以下范围使用创造性判断：

1. **相关性判断**：根据 JD 给已确认经历排序，不能新增经历。
2. **表达优化**：改善动词、结构和信息密度，不能改变主体、时间、数字、工具和结果。
3. **叙事组织**：选择最能支持岗位的真实项目构成求职信，不能制造动机或行业经验。
4. **研究综合**：选择检索路径并连接多个可靠来源；事实必须有来源，推断必须标记，未知必须保留。
5. **问题预测**：从 JD 和最终简历推导面试问题；必须说明问题来源，不能把预测说成真实面试流程。
6. **复盘解释**：在用户原始反馈之上归类和提出训练动作；不得改写用户经历或仅凭一次事件下永久结论。

## Agent 永远不能决定的事项

- 事实是否真实、缺失信息应填什么；
- 用户是否已经批准全部文件；
- 收件人不明确时选择哪个地址；
- 是否对外发送邮件或是否重试；
- 是否获得面试、面试结果是什么；
- 是否把单次反馈升级为长期个人规律；
- 是否跳过状态、哈希、视觉检查或回执。

## 输出契约

### 投递草稿

Agent 必须返回一个 JSON 对象，且只有三个字段：

- `resume_markdown`
- `cover_letter_markdown`
- `evidence_map_markdown`

程序将其保存为三个固定文件。Evidence Map 必须包含 `Claim Mapping` 和 `JD Gaps`；程序只校验结构，用户仍需确认事实和质量。通过结构校验只代表“可审阅”，不代表“已批准”。

### 面试材料

面试文档必须按固定顺序包含九个章节：证据边界、公司概览、业务流程、JD 拆解、简历匹配、公司与岗位问题、简历追问、模拟面试与清单、来源台账。在线材料必须提供 URL，且使用 `[Verified]`、`[Inference]`、`[Unknown]` 标记证据状态。

### 契约失败

缺少文件、字段、章节、来源或证据标记时，程序停止在当前状态并报告具体缺口。不得让 Agent 自动删减要求、用散文替代结构、伪造占位信息或自行推进下一阶段。

## 可预期不等于内容完全相同

同一 JD 可以有不同但都合理的表达和问题预测。CareerFlow 保证的是：输入来源固定、Agent 可变范围固定、输出骨架固定、事实边界固定、人工决定固定、外部动作可追溯。它不保证不同模型逐字生成相同内容，也不会把这种不可控目标伪装成确定性。
